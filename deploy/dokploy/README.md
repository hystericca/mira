# Mira Web on Dokploy

Mira's browser build is generated by Dawn under `out/mira-release/wasm`.
The DigitalOcean deploy path keeps that expensive build local, uploads the
static WASM bundle to the VPS, and lets Dokploy/Traefik serve it with HTTPS.

## Build and Upload

```sh
tools/deploy_web.sh
```

Useful overrides:

```sh
BUILD=0 tools/deploy_web.sh
REMOTE=root@146.190.141.170 tools/deploy_web.sh
MIRA_WEB_ROOT=/opt/mira-web tools/deploy_web.sh
```

The script publishes releases under `/opt/mira-web/releases/<timestamp>` and
updates `/opt/mira-web/current`.

## Dokploy Compose

Create a Docker Compose service in Dokploy and use:

- Compose path: `deploy/dokploy/docker-compose.yml`
- Domain: `mira.hystericca.dev`
- Container port: `8080`
- Optional env: `MIRA_DOMAIN=mira.hystericca.dev`
- Optional env: `MIRA_WEB_ROOT=/opt/mira-web`

The compose file includes Traefik labels for Dokploy's `dokploy-network` and
Let's Encrypt resolver. The Caddy config is uploaded to
`/opt/mira-web/Caddyfile` by `tools/deploy_web.sh`, so the compose can also be
pasted into Dokploy directly if you are not deploying from Git yet.

## DNS

Point the `mira.hystericca.dev` A record at the VPS public IPv4 before expecting
the Let's Encrypt certificate to issue.
